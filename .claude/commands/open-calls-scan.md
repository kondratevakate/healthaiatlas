# /open-calls-scan

High-fidelity scan for currently-open application calls (grants, accelerators,
hackathons, conference CFPs) relevant to AI in healthcare. Drives a real
Chrome via `chrome-devtools-mcp` to bypass Cloudflare/JS-shell pages that
the cloud `routine trig_01SR4rdtLYQxd7Gprhg4ht9Q` cannot reach.

Complementary to the daily cloud routine — runs **on-demand** in an
interactive Claude Code session. Both write to the same `routines/open-calls/inbox/`
directory and dedup against each other.

## Workflow you must follow

### Step 0 — Preflight
Run `mcp__plugin_chrome-devtools-mcp_chrome-devtools__list_pages`. If the
MCP server is not connected, abort and tell the user: "chrome-devtools-mcp
not connected. Enable it in plugin settings, then re-run /open-calls-scan."

Get today's UTC date with `date -u +%Y-%m-%d`. Store as `TODAY`.

### Step 1 — Load the seed list
Read `routines/open-calls/SOURCES.md`. Extract every URL listed under the
five Tier sections. Skip URLs explicitly marked `(low-yield)` in the list.

### Step 2 — Crawl each seed URL via Chrome
For each URL:

1. `mcp__plugin_chrome-devtools-mcp_chrome-devtools__new_page` with the URL
   (use `background: true` after the first to keep the user's foreground tab clean).
2. Wait briefly for hydration. Use
   `mcp__plugin_chrome-devtools-mcp_chrome-devtools__wait_for` with a list
   of expected words (`["Apply", "Deadline", "Program", "Cohort", "Application", "Submit"]`)
   and a 6000 ms timeout. If timeout fires, continue anyway.
3. Run `evaluate_script` to extract structured data:
   ```js
   () => {
     const text = document.body.innerText;
     const dates = text.match(/\b(?:January|February|March|April|May|June|July|August|September|October|November|December)\s+\d{1,2},?\s+20\d{2}\b/gi) || [];
     const isoDates = text.match(/\b20\d{2}-\d{2}-\d{2}\b/g) || [];
     const deadlineCtx = text.match(/.{0,80}(?:deadline|due|submit|propos|abstract|solution summary|closes?|application|cohort|cut-?off|intake).{0,180}/gi)?.slice(0, 8) || [];
     return {
       title: document.title,
       url: location.href,
       chars: text.length,
       headings: [...document.querySelectorAll('h1, h2, h3')].slice(0, 12).map(h => h.innerText.trim()),
       dates: [...new Set([...dates, ...isoDates])],
       deadline_contexts: deadlineCtx,
       apply_links: [...document.querySelectorAll('a')]
         .filter(a => /apply|submit|cohort|register|application/i.test(a.innerText))
         .slice(0, 5)
         .map(a => ({ text: a.innerText.trim(), href: a.href }))
     };
   }
   ```
4. If `apply_links` contain a clear next-step URL on the same domain and the
   parent page had no concrete deadline, navigate to the apply link and
   repeat the extraction once. Do not follow apply links to off-domain
   third-party platforms (typeform, lever.co, smartrecruiters, etc.) —
   record the apply URL as the canonical link instead.

If navigation fails (DNS, timeout, 403), record the URL in `failed_sources`
with the failure reason and continue.

### Step 3 — Supplement with up to 3 WebSearch queries
Run at most 3 queries from the `Search query patterns` section of SOURCES.md.
For every promising hit, navigate Chrome to the official page and extract
via the same `evaluate_script` block. Never include a result based on a
search snippet alone — every entry must have been read by Chrome on the
funder's own domain.

### Step 4 — Filter
Keep a candidate only if ALL hold:
- Deadline parses to a date strictly after `TODAY`. Skip "rolling" entries
  unless the page explicitly states a current cohort window.
- Eligibility includes startups OR independent researchers OR academic PIs.
- Topic is AI/ML applied to health.
- Canonical URL is on the funder's own domain (not an aggregator, not a
  Jina Reader proxy, not a CDN).

### Step 5 — Dedup against the last 7 days
`ls routines/open-calls/inbox/` and read every `.md` file dated within the
last 7 days (this catches both cloud-routine and prior chrome-scan files).
Build a set of `(program_name_normalized, deadline)` tuples already seen.
Drop matching candidates.

### Step 6 — Score and trim
Sort by tier (UAE > MENA > Global > Accelerators > CFPs), then by earliest
deadline first. Keep at most 12.

### Step 7 — Decide on output
If trimmed list is empty, print `No new calls found via Chrome scan.` and
exit without committing. Do NOT open a PR.

### Step 8 — Write digest
Create branch `chrome-scan/open-calls-<TODAY>` from `main`. Write
`routines/open-calls/inbox/<TODAY>-chrome.md`:

```markdown
# Open calls digest — <TODAY> (Chrome scan)

_Generated by /open-calls-scan via chrome-devtools-mcp. <N> calls verified by direct DOM extraction on funder domains._

## UAE
### <Program name>
- **Deadline:** YYYY-MM-DD
- **Eligibility:** one line
- **Topic fit:** one line on why it matches HealthAI Atlas
- **Link:** <canonical funder URL>
- **Verified on:** <TODAY> (Chrome DOM)
- **Evidence:** <quoted deadline string from the page, e.g. "Solution Summary Due: June 25, 2026, 12:00PM ET">

(repeat per entry, omit empty sections)
## MENA
## Global
## Accelerators
## Conference CFPs
```

The **Evidence** field is the key quality marker — it must be a literal
quote from the page DOM, not a paraphrase. This is what distinguishes
Chrome-scan entries from cloud-routine snippet entries.

Append one line to `routines/open-calls/index.md`:
`- <TODAY> — N calls via Chrome (X UAE, Y MENA, Z global, A accel, B CFP)`.

If any URLs failed even with Chrome, append a footer:
```
---
## Sources that failed to fetch this run
- <url> — reason
```

### Step 9 — Commit and PR
- `git add routines/open-calls/inbox/<TODAY>-chrome.md routines/open-calls/index.md`
- Commit message: `routine: chrome-scan open calls <TODAY>` with Claude
  Co-Authored-By trailer.
- Push branch `chrome-scan/open-calls-<TODAY>`.
- Open PR: `gh pr create --base main --title 'Chrome-scan open calls <TODAY>' --body '<digest body>' --label routine`. If `gh` is not in PATH, print the
  manual PR URL: `https://github.com/kondratevakate/healthaiatlas/compare/main...chrome-scan/open-calls-<TODAY>` and tell the user to open it.

### Step 10 — Summary
Print to the user:
- `Created PR: <url>` (or `Branch pushed, open PR manually: <url>`)
- `Entries: N total (breakdown by tier); F sources failed`
- Time spent: rough estimate in minutes

## Constraints

- All text in English (project rule).
- Never invent program details. If DOM extraction yielded no concrete
  deadline, drop the entry — do not fall back to "rolling" or guessed dates.
- Maximum 12 entries per digest.
- Modify only files inside `routines/open-calls/`.
- No `git push --force`, no direct commits to `main`, no merging your own PR.
- Close all Chrome tabs you opened at the end of the scan (call
  `mcp__plugin_chrome-devtools-mcp_chrome-devtools__close_page` for each).
- This command is **read-mostly** with respect to the open web. Do not click
  Apply buttons, submit forms, or interact with the page beyond reading.
